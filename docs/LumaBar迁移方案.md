# 留白 × LumaBar：UI 统一与设置迁移方案

> 已按用户 2026-11-02 的最新要求停止完整迁移，收敛为核心待办栏。以下为历史方案，不代表当前实施范围。当前仅保留待办、本地保存、触顶显示/移出隐藏，以及轻量设置；独立设置窗口、外观预览和底部任务栏功能均不在当前范围内。

分析日期：2026-11-02。当前阶段仅分析和规划，未修改应用实现或用户配置。

## 目标与规划假设

按「留白承接 LumaBar 的任务栏功能，提供统一设置入口」规划。顶部栏保留左右分布、中间留白、触顶显示及鼠标移出立即隐藏；待办继续使用当前数据文件。Windows 底部任务栏的自动明暗和玻璃材质作为独立功能模块迁入。

来源为 LumaBar GitHub main；README 标注 0.6.5。分析内容包含设置、外观、应用规则和深色截图，以及 App.cs、Ui.cs、AppearanceEditor.cs、Core.cs、Materials.cs、Storage.cs、native/README.md 和 settings.json。

LumaBar 采用 .NET Framework 4.8 + WinForms 自绘控件。留白继续使用 WinUI 3，借鉴其视觉规范与交互，而非直接嵌入旧窗体。

## 一、UI 规范

| 项目 | LumaBar 的实现依据 | 留白的适配方案 |
|---|---|---|
| 强调色 | 浅色 #0F705B；深色 #8BE0C2 | 统一到 WinUI 主题资源，作用于选中导航、主要按钮、勾选和滑块 |
| 页面背景 | 浅色 #F5F7F7；深色 #1C1F23 | 设置页采用稳定底色，区分页面与内容卡片 |
| 内容表面 | 浅色 #FFFFFF；深色 #25292D | 卡片、规则编辑区与分组共用层级 |
| 边框 | 浅色 #DAE3DE；深色 #424C48 | 细边框，统一悬停、聚焦和禁用状态 |
| 次要文字 | 浅色 #64746F；深色 #A9B6B2 | 描述、状态和提示统一弱化，不降低关键错误可见性 |
| 排版 | 微软雅黑 UI，标题、正文、说明分层 | 建立统一字号、字重与行高资源，按 DIP 布局 |
| 形状 | 圆角导航、按钮、输入框、菜单 | 统一控件圆角与面板圆角；保留原生键盘交互 |
| 布局 | 品牌/标题/副标题、分类导航、内容、底部操作 | 独立设置窗口；分类多时使用左侧导航，底部固定操作栏 |
| 材质 | 设置界面以清晰的实体内容区为主 | 顶部栏和待办保留 Acrylic；设置内容区优先保证阅读和对比度 |

建议以 4/8/12/16/24 DIP 间距、8 DIP 控件圆角、12 DIP 面板圆角作为留白统一规范起点；这些是本项目的拟定值，不是原仓库所有控件的原始尺寸。

设置 UI 跟随 Windows 的应用配色；底部任务栏自动明暗属于系统模式，两者分开管理，避免设置界面跟着检测结果来回变色。

## 二、设置入口与页面结构

最右侧齿轮打开独立的「留白设置」窗口。窗口不会因鼠标移出而关闭；切换分类保留未保存草稿。关闭时有改动则询问保存或放弃。

建议分类：

1. 常规：统一开机启动、启动后隐藏、数据文件夹、导入 LumaBar 配置。
2. 顶部栏与待办：顶部栏材质/配色及待办外观；保留中间留白和当前隐藏行为。涉及新增可调参数时再按实际需求开放。
3. Windows 任务栏：自动明暗策略、切换节奏、场景材质、显示器与可读性保护。
4. 应用规则：进程名、自动/浅色/深色/保持原模式，添加、编辑、删除和校验。
5. 高级与恢复：高级检测参数、忽略进程、暂停与恢复、重新同步、材质重试及运行状态。
6. 关于：版本、开源许可和第三方组件声明。

待办窗口仍是轻量浮层。设置窗口不复用当前 388 DIP 宽的小面板，以容纳显示器、场景、颜色与规则等完整配置。

## 三、设置迁移清单

| 来源 | 迁移内容 | 目标位置与实现条件 |
|---|---|---|
| 常规 | 当前用户开机启动 | 与留白合并为一个入口；旧 LumaBar 启动项在正式切换时处理 |
| 常规 | 灵敏、均衡、舒缓、自定义 | Windows 任务栏 → 自动明暗；保留现有自定义参数 |
| 主界面 | 自动、固定浅色、固定深色、仅检测 | Windows 任务栏 → 自动明暗；先保留原来手动模式不跨重启保存的语义 |
| 应用规则 | auto/light/dark/hold | 原样迁移进程规则，继续仅对最大化/全屏场景生效 |
| 玻璃设置 | Enabled、TaskbarRegion、AutoContrast、PerMonitor | Windows 任务栏 → 外观；依赖材质与壁纸分析服务 |
| 场景 | Desktop、Window、Maximized | 桌面、普通窗口/分屏、最大化/全屏分别编辑 |
| 材质 | normal、clear、blur、acrylic、opaque | Windows 任务栏外观；保留不同材质的可用参数关系 |
| 染色 | 自动染色、自定义色、TintOpacity、BlurRadius、ShowLine | 颜色、染色不透明度、模糊强度、顶部分隔线 |
| 预设 | 清透玻璃、柔和磨砂、浓厚亚克力、系统默认 | 外观页提供一键预设；不覆盖未编辑显示器的设置 |
| 多屏 | MonitorOverrides 与独立启用状态 | 默认外观＋选中显示器覆盖；保留继承关系 |
| 高级 | 六项计时参数、明暗阈值、HoldOwnedDialogs、HoldMediaPlayers、IgnoredProcesses | 高级页，不挤入常规设置；保留校验范围及 TimingVersion 迁移逻辑 |
| 状态/维护 | 检测依据、已确认场景、材质连接/应用/降级/恢复状态 | 高级与恢复，提供重新同步和重试入口 |
| 暂停/退出 | 恢复本程序管理的主题与任务栏材质 | 统一生命周期服务，保留原有恢复与外部更改保护 |

底部任务栏的透明/模糊玻璃不能直接视为 WinUI 顶部窗口的同一套材质 API。顶部窗口使用 WinUI 系统背景，底部任务栏使用 LumaBar 原生后端，配置与预览目标必须明确分开。

## 四、保存与预览

- 普通设置：编辑草稿，点击「保存并应用」提交；取消保留原配置。
- 外观：临时预览，保存后保留，取消或放弃草稿时恢复。
- 切换分类或仅打开设置不写入文件、不修改系统主题。
- 无效参数就地提示；应用规则统一进程名，检查空白与重复。
- 待办内容继续即时保存，不纳入设置页的保存事务。
- 设置窗口显式关闭；顶部栏和待办浮层继续按鼠标位置立即隐藏。

## 五、代码与配置迁移

1. 建立 WinUI 共享主题资源及可复用的设置行、分组卡片、说明、状态、主要/次要按钮样式。
2. 拆分独立 SettingsWindow，避免继续在 PanelWindow.BuildSettings 中堆叠完整设置。
3. 将 LumaBar 的检测决策、壁纸分析、规则、主题写入及恢复拆为服务；适配 .NET 10 的序列化、计时、窗口取样和线程模型。材质 COM 调用保留专用 STA 工作线程。
4. 将留白顶部栏、待办、设置和弹窗加入自动检测排除范围，防止界面影响自身判定。
5. 增加 settings.json 存放新项目配置，与现有 todos.json 分开；配置带版本号并使用原子保存及备份。
6. 导入旧版 settings.json：完整保留规则、计时、Glass、MonitorOverrides 和 TimingVersion；检查并展示导入结果，确认应用前不改动旧程序配置。
7. 不将正在运行的旧 session.json 直接当作新会话使用。正式切换先让旧程序正常退出并恢复，再由新服务记录自己的恢复日志。
8. 正式整合后只由一个进程管理系统主题与任务栏材质，避免两套引擎互相覆盖。保留 ExplorerTAP 固定版本、校验和、上游声明及恢复机制。

## 六、实施顺序与验收

### 第一阶段：统一可见界面

建立主题资源、独立设置窗口及分类导航；先接入留白已存在的开机启动与数据入口，并同步顶部栏、待办、编辑对话框样式。验收浅/深主题、DPI、键盘操作、鼠标隐藏与草稿保留。

### 第二阶段：迁移配置与决策

实现完整配置模型和旧配置导入，移植自动明暗、应用规则及切换节奏。先使用模拟主题后端验证；确认只有「保存并应用」提交修改。

### 第三阶段：迁移任务栏外观

接入材质后端、场景预设、染色、模糊、显示器覆盖及预览回滚。每项设置在对应后端可运行后再开放使用。

### 第四阶段：恢复与整体验收

验证暂停、退出、异常退出后的恢复，外部主题修改保护，锁屏/休眠、高对比度及 Explorer 重新启动。核对真实材质状态与界面提示；完成主屏与实际多屏测试，再切换统一启动入口。

完成标准：设置可保存并在重启后还原；旧规则与外观可导入；预览取消能恢复；待办不受影响；没有无后端支撑的设置选项；独立设置窗口不因鼠标移出消失。
