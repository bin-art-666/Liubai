# 扫码客户端兼容性核查

核查日期：2026-11-07。本记录不包含二维码载荷、授权 UUID、账号凭据或聊天内容。

## 当前本机证据

- 微信 Windows 版本为 4.1.15.56。
- 本机注册了 `weixin:` 协议，处理程序为本机微信。这仅证明系统可以唤起微信，不能证明可以传入任意网页地址，更不能证明微信会完成网站授权。
- 实际查看微信主界面右上角加号菜单，只有“发起群聊”“添加朋友”“写笔记”，没有独立扫一扫入口。未据此推断其他界面不存在识别图片功能。
- 未发送消息、提交登录授权、调用未公开接口或将授权地址改写为猜测的客户端协议。

## 同类方案及局限

作者发布的 [Quicker“微信打开二维码”](https://getquicker.net/Sharedaction?code=f974f5ed-a6fa-4c27-4dbf-08dcc04bd41a) 说明其路径是：框选图片、在微信自己的对话中粘贴、打开图片、识别图中二维码。作者同时明确指出，大多数扫码登录仍需手机，主要可用场景是部分公众号跳转。这是该工具作者的适用性说明，不是 DeepSeek 在当前微信版本的测试结果。

## DeepSeek 状态

**尚未验证电脑版微信可完成 DeepSeek 登录。** 当前本地修复只阻止已知微信/QQ 授权链接自动进入 Edge，并显示处理说明；没有接入微信图片识别适配器，没有实现免手机登录。

下一步由用户手动完成一次最短验证：

1. 在原 DeepSeek 登录页刷新微信二维码，截取新的二维码图片。
2. 使用微信已有的图片查看/识别功能识别该图片。若需经自己的对话发送图片，由用户自行操作。
3. 记录是否有“识别图中二维码”，识别后是否出现授权确认，确认后原 DeepSeek 网页是否真正登录。
4. 只反馈结果文字；不保存或回传二维码、UUID、cookie、授权码。

若本机微信不提供识别，或结果仍要求手机，则此环境不满足免手机接入的前提。若真实授权成功，再设计客户端适配器与明确的用户触发动作，避免将“唤起客户端”当成“登录成功”。

自动化技能禁止操作身份验证界面，最终授权步骤必须由用户手动执行。核查完成前，不把 DeepSeek 标记为支持电脑版微信登录。
