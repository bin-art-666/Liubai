# 内置工具扩展约定（第四阶段）

本阶段建立同一可执行程序中的内部接入框架。没有扫描外部 DLL、执行脚本插件、安装商店或新增工具；现有图标、配置文件、默认顺序和面板视觉保持原有设计。

## 工具目录

`ToolCatalog` 是稳定 ID、名称、默认顺序、入口类型和能力的唯一来源。入口分为操作、面板、开关；能力包括拖入、按住预览和右键菜单。设置入口标记为必须保留；待办和随手记指向同一 `records` 面板组。

`ToolbarOrder` 从目录获取默认项，保留原有旧配置排序迁移；顶栏布局、更多面板和设置名称从同一目录读取。目录不持有 UI 或服务实例，不会因此加载 AI、开启摄像头或读中转站项目。

## 宿主与 UI

每个显示器的顶栏拥有一个 `ToolHost<DataPackageView>`。`BarTools.InitializeToolHost` 将编译内置的工具映射到现有按钮、操作、活动状态、拖入接收和右键菜单工厂。全部注册通过校验后封闭，不允许运行中注入任意代码。

主点击统一经宿主分发，检查模态／休眠／退出状态，并防止同一工具并发执行。工具异常记录到本机 `tools.log`，返回失败，其他工具继续可用。右键菜单保留原交互；更多面板仍为不同 XamlRoot 创建独立菜单，临时移动原按钮，不复制点击处理器。

拖入只接收明确交给宿主的 DataPackage，不读取环境剪贴板。能力声明必须同时提供接收条件和处理函数；不支持的载荷返回拒绝。中转站保持悬停展开和拖入停留保护，AI 保持附件暂存及确认发送。Ctrl 复制拖入不受按钮排序的 Ctrl 点击抑制规则影响。

面板打开状态和高亮从注册的查询函数读取。按住预览由 Peek 能力选择入口，调用独立预览展示，不代替主点击或创建编辑器。

## 面板与保存

`PanelLifecycle` 统一模态查询、收起、保存和释放：

- 普通切换只收起停靠面板；显式隐藏全部时可收起独立窗口。固定／拖入保护继续由 `PanelWindow` 决定。
- 保存失败立即返回失败，退出和更新流程保留当前程序；释放之前等待宿主内已经开始的操作结束。
- 释放只做一次，个别面板释放失败仍继续清理其他面板。注册保存或状态检查不会创建未使用的窗口。
- 待办／随手记共用一个面板参与者；正式多屏的共享记录面板由 `BarManager` 保存和销毁，各显示器不重复销毁它。
- AI 浏览器和摄像头等应用级服务继续由 App 的既有服务生命周期管理。关闭一块屏幕的面板不会停止后台提醒或销毁共享 AI 服务。

代码运行在 UI 调度线程，宿主不是多线程任务队列。保存等待期间应用退出／维护的宿主门禁阻止新点击；系统提醒调度仍采用原有的持久化与暂停规则。

## 接入一个新内置工具

1. 在目录追加稳定 ID、名称、类型和能力；已发布 ID 不改名、不复用。
2. 使用现有 `CreateToolbarButton`、统一线条图标和 `PanelTheme` 构建入口／面板，在 `InitializeToolHost` 注册行为。能力没有处理器或工具漏注册会在启动时明确失败。
3. 有面板时注册一个生命周期参与者；共享面板只注册一次。额外应用级资源使用第二阶段的按需服务，明确保存、暂停与释放边界。
4. 新工具会进入目录驱动的排序、布局与更多流程；保持菜单按 XamlRoot 创建，拖入不直接上传，隐藏入口不等于停掉后台任务。
5. 扩展接口检查和隔离原生检查，确认旧配置、二次点击、拖入、保存失败及关闭行为。

配置和 UI 仍由统一主题控制，本阶段不改变数据格式。未来若开放外部插件，需要另行设计隔离、权限、签名和版本兼容，当前框架不承诺这些能力。

2026-11-07 验证：54 项接口检查、131 项外观检查、39 项布局检查及 115 项原生检查通过。原生宿主验证实际按钮点击、二次收起、共享标签、高亮、明确拖入、保存与资源释放；真实 BarManager 验证活动计时退出确认及取消后继续运行。未调用真实摄像头或隐私设备开关，AI 使用既有本机 HTML 回归，不上传或发送内容。
