# 功能生命周期（第二阶段）

所有功能仍在同一个留白程序中。`FeatureModule<T>` 负责 UI 线程上的延迟创建、状态窥视、失败后重试以及显式释放；它不是动态插件加载器。

| 功能 | 启动时 | 使用时 | 收起时 / 结束时 |
| --- | --- | --- | --- |
| AI | 只读配置；工具栏、设置、显示器变更和隐藏操作不创建服务 | 首次打开创建服务和面板，按服务创建 WebView2 | 保留对话并降低浏览器内存目标；退出关闭所有网页并解除配置订阅 |
| 摄像头守护 | 不创建服务，不枚举或打开摄像头 | 明确启用后才打开摄像头 | 关闭、暂停、锁屏、睡眠取消检测并等待释放摄像头；暂停恢复计时保留 |
| 截图 / OCR / 扫码 | 不创建识别和编码资源 | 操作时按需创建 | 流和图片按操作释放，预览收起释放图片；原有生命周期保持 |
| 待办 / 随手记 | 加载提醒必要数据，面板不创建 | 编辑与预览按需显示 | 完成保存，停止日期刷新，释放列表与图片视图；保留编辑器草稿和撤销状态 |
| 中转站 | 专注状态和其他工具不提前加载项目数据；设置分组展开后才加载 | 创建数据存储及界面，限量加载缩略图 | 取消缩略图任务、清空图片缓存与卡片，停止刷新；下次打开重建视图 |
| 工作现场 | 专注栏只读工作现场元数据 | 每个数据源首次使用时附加监听 | 跟踪已加载数据源，不为自动关联强制加载其他存储 |
| 提醒 / 时钟 | 恢复持久化调度 | 独立于面板可见性运行 | 隐藏入口不会取消提醒；锁屏、睡眠沿用暂停与恢复机制 |
| 隐私保护 | 读取设备恢复日志以保留恢复提示 | 用户明确操作时枚举或变更设备 | 不因隐藏面板更改设备状态 |

失败隔离：模块工厂失败不缓存半成品，不影响其他模块，下一次调用可重试；释放失败保留资源所有者。现有 AI 页面恢复、摄像头错误提示、保存失败保留编辑器的行为继续使用。不开启任意代码插件。

验证：`tests/FeatureModuleChecks` 检查被动状态读取、重复消费者、初始化失败重试、独立模块、释放失败与重建。原生 `--verify-modules --data-dir <隔离目录>` 检查冷启动、设置读取、工作现场懒绑定、AI 服务释放与重建；原有 workflow、AI、守护、记录、时钟测试覆盖真实界面和资源行为。

不承诺固定内存或 CPU 降幅。此阶段可验证的是初始化和资源持有边界，内存还受 WebView2、系统文件缓存和使用过的内容影响。隐藏 AI 不强制挂起脚本，以保留网站生成、上传等进行中的操作。

2026-11-06 验证完成：311 项基础检查和 80 项原生检查通过。守护使用模拟摄像头，未调用真实摄像头。中转站的后台导入测试仅在准备模拟数据时保持面板，真实拖入停留与外部焦点收起仍单独验证。原生 Windows 提醒注册与投递通过。空闲进程数据仅作运行记录，未作同条件前后性能比较。
